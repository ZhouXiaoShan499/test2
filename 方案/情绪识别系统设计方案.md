# MindBloom 情绪识别系统设计方案

## 一、项目概述

### 1.1 项目背景
结合 MindBloom 的情绪价值功能，构建一个能够识别用户生理状态（如鼠标使用疲劳、酸痛感等）并转化为情绪洞察的系统。通过设备交互数据采集 + 用户自报告 + MindBloom 情绪卡片，形成完整的情绪 - 生理关联图谱。

### 1.2 核心目标
- **识别**：通过设备交互数据识别用户的生理疲劳、压力状态
- **映射**：将生理状态映射到 MindBloom 情绪标签体系
- **记录**：多重冗余记录，确保数据不丢失
- **可视化**：在 MindBloom 视觉卡片中展示情绪 - 生理关联

## 三、数据采集方案（人工采集）

### 3.1 设备交互数据采集

#### 3.1.1 鼠标数据采集
| 指标 | 采集方式 | 情绪映射 |
|------|----------|----------|
| 点击频率 | 记录单位时间点击次数 | 高频→焦虑/急躁 |
| 移动速度 | 计算光标移动速度 | 过快→紧张，过慢→疲劳 |
| 停留时间 | 记录鼠标静止时长 | 长时间静止→分心/疲惫 |
| 轨迹平滑度 | 分析移动轨迹的流畅性 | 抖动→压力/不安 |
| 滚动模式 | 记录滚动频率和幅度 | 快速滚动→焦躁 |

#### 3.1.2 键盘数据采集
| 指标 | 采集方式 | 情绪映射 |
|------|----------|----------|
| 打字速度 | 计算按键间隔时间 | 过快→焦虑，过慢→犹豫/疲劳 |
| 错误率 | 记录退格键使用频率 | 高错误率→压力/分心 |
| 按键持续时间 | 记录按键按下到释放的时间 | 长时间按压→紧张/犹豫 |
| 输入中断 | 记录长时间无输入间隔 | 频繁中断→思绪混乱 |

#### 3.1.3 应用使用数据采集
| 指标 | 采集方式 | 情绪映射 |
|------|----------|----------|
| 应用切换频率 | 记录窗口切换次数 | 高频切换→注意力分散/焦虑 |
| 屏幕时长 | 累计活跃使用时间 | 过长→逃避/内耗 |
| 内容类型 | 识别应用类别 | 社交媒体→空虚感风险 |

## 四、MindBloom 情绪价值整合

### 4.1 情绪标签映射体系

```
生理信号 → 情绪推断 → MindBloom 标签

【疲劳类】
鼠标移动迟缓 + 打字间隔长 + 长时间静止
    ↓
推断：身体疲劳 / 精神疲惫
    ↓
MindBloom 标签：#疲惫 #需要休息 #能量低

【压力类】
鼠标快速抖动 + 高频点击 + 应用频繁切换
    ↓
推断：焦虑 / 紧张 / 压力
    ↓
MindBloom 标签：#焦虑 #压力 #需要放松

【内耗类】
长时间社交媒体使用 + 快速滚动 + 无明确目标
    ↓
推断：空虚 / 迷茫 / 内耗
    ↓
MindBloom 标签：#内耗 #空虚 #需要反思
```

## 五、冗余记录机制设计

### 5.1 三级备份架构

```
┌─────────────────────────────────────────────────────────────────┐
│                        数据流                                    │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  采集 → 主缓存 → 实时写入 → 主数据库 → MindBloom 同步           │
│                    ↓                                            │
│              异步写入 → 本地日志文件 (JSON)                      │
│                    ↓                                            │
│              定时打包 → 外部备份 (加密 ZIP)                      │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 5.2 故障检测与切换

```python
# 伪代码：故障检测机制

class RedundantLogger:
    def __init__(self):
        self.primary_db = MindBloomLocalDB()
        self.log_file = "emotion_logs.jsonl"
        self.backup_dir = "backups/"
        self.cache = []  # 内存缓存
        
    def log(self, data):
        # 1. 先写入内存缓存（最快）
        self.cache.append(data)
        
        # 2. 尝试写入主数据库
        try:
            if self.primary_db.is_healthy():
                self.primary_db.insert(data)
            else:
                raise ConnectionError("主数据库不可用")
        except:
            # 主数据库故障，数据已在缓存中，不会丢失
            self._fallback_to_file(data)
        
        # 3. 异步写入日志文件（双重保障）
        self._async_write_to_file(data)
        
        # 4. 缓存满时触发备份
        if len(self.cache) >= 1000:
            self._flush_cache()
            
    def _fallback_to_file(self, data):
        """主数据库故障时的降级方案"""
        with open(self.log_file, 'a', encoding='utf-8') as f:
            f.write(json.dumps(data) + '\n')
            
    def _async_write_to_file(self, data):
        """后台线程写入日志文件"""
        # 不阻塞主流程
        pass
        
    def _flush_cache(self):
        """将缓存数据批量写入"""
        # 恢复主数据库后批量同步
        pass
```

### 5.3 数据恢复机制

```
故障恢复流程：
1. 检测到主数据库恢复
2. 读取本地日志文件中未同步的数据
3. 按时间戳合并到主数据库
```
